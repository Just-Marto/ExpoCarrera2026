¿Qué acaba de pasar?

Usaste una técnica llamada SQL Injection. En vez de escribir un nombre de usuario real, escribiste un fragmento de código SQL que engañó a la base de datos.

Lo que escribiste:

Usuario: {{ payload_user }}
Contraseña: {{ payload_pass }}

La consulta que ejecutó el servidor:

{{ query }}

¿Por qué funcionó?

1

El programador concatenó tu input directo en la consulta SQL, sin limpiarlo.

2

Tu comilla ' cerró el string que abrió el programador, y lo que sigue se interpreta como código SQL.

3

OR '1'='1' es una condición que siempre es verdadera, así que la base devuelve el primer usuario.

¿Cómo se previene?

Con consultas parametrizadas: los datos del usuario viajan separados del comando SQL. Así la base de datos nunca confunde datos con instrucciones.

❌ Vulnerable (concatenación)
f"SELECT * FROM usuarios WHERE username = '{username}'"
✅ Segura (parametrizada)
cursor.execute("SELECT * FROM usuarios WHERE username = ?", (username,))
