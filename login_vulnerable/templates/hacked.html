¿Que acaba de pasar?

Usaste una tecnica llamada SQL Injection. En vez de escribir un nombre de usuario real, escribiste un fragmento de codigo SQL que engano a la base de datos.

Lo que escribiste:

Usuario: {{ payload_user }}
Contrasena: {{ payload_pass }}

La consulta que ejecuto el servidor:

{{ query }}

¿Por que funciono?

1

El programador concateno tu input directo en la consulta SQL, sin limpiarlo.

2

Tu comilla ' cerro el string que abrio el programador, y lo que sigue se interpreta como codigo SQL.

3

OR '1'='1' es una condicion que siempre es verdadera, asi que la base devuelve el primer usuario.

¿Como se previene?

Con consultas parametrizadas: los datos del usuario viajan separados del comando SQL. Asi la base de datos nunca confunde datos con instrucciones.

❌ Vulnerable (concatenacion)
f"SELECT * FROM usuarios WHERE username = '{username}'"
✅ Segura (parametrizada)
cursor.execute("SELECT * FROM usuarios WHERE username = ?", (username,))
